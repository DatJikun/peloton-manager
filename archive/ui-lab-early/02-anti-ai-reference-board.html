Peloton Manager · anti-AI reset

Najpierw prawdziwe produkty, potem projekt

Poprzednie makiety odrzucamy. Ich problemem nie był kolor, tylko sposób myślenia.

Równy grid kartAI rozdzieliło ekran na estetycznie równe moduły, mimo że decyzja o składzie jest ważniejsza od budżetu i morale.
Rytualne KPICztery duże liczby pojawiły się dlatego, że „dashboard powinien mieć KPI”, a nie dlatego, że manager musi je zobaczyć właśnie teraz.
Styl przed pracąRoadbook, ledger i control room były kostiumami. Nie wynikały z faktycznego przepływu: wiadomość → analiza → decyzja → konsekwencja w świecie.
Idealne daneKażdy tekst miał wygodną długość, każdy stan był kompletny. Prawdziwa gra musi wytrzymać długie nazwiska, braki wiedzy, 30 wiadomości i konfliktujące rekomendacje.
REFERENCE 01

Football Manager

Nie udaje lekkiej aplikacji. Gęstość informacji jest częścią fantazji o wykonywaniu zawodu.

  • stała nawigacja jako infrastruktura;
  • jeden dominujący kontekst: następny mecz;
  • tabele i tekst mają pierwszeństwo przed dekoracją;
  • delegowanie złożoności, nie jej ukrywanie.
Źródło obrazu: TechRadar / Sports Interactive
REFERENCE 02

Motorsport Manager

Ekran nie jest abstrakcyjnym dashboardem — ma konkretny obiekt świata: bazę zespołu. UI objaśnia to, co gracz właśnie ogląda.

  • duży obiekt świata zamiast ściany kart;
  • globalny czas, finanse i następny wyścig stale widoczne;
  • pełna, długa nawigacja nie jest traktowana jak błąd;
  • Continue jest częścią głównej pętli.
Źródło obrazu: Steam / Playsport Games
REFERENCE 03

Pro Cycling Manager

Najbliższa domena. Dashboard jest operacyjną skrzynką dnia, z osią czasu sezonu i bez prób zamiany każdej informacji w osobny widget.

  • data i Continue zamykają pętlę dnia;
  • wiadomości są roboczym strumieniem, nie ozdobnym modułem;
  • proste powierzchnie mieszczą dużo treści;
  • tożsamość kolarska wynika z danych i kontekstu.
Źródło obrazu: Cyanide Studio
